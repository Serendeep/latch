title: "Managing your vault"

## Projects and environments

Add a project in the manager and select its directory. The directory binds CLI requests to that project. If you move the project, use **Change directory…** to bind the new location. Each project starts with development, test, staging, and production environments. Select the environment before creating, importing, revealing, or copying secrets.

## Import and expected names

Import a `.env` file through the native picker and review the names before committing. Existing names are reported as conflicts. Import does not erase the original plaintext file.

Compare a `.env.example` to find expected variable names. Latch discards the right-hand sides rather than importing example values as secrets. The parser does not execute shell expressions.

## Reveal and copy

Values are concealed by default. Reveal deliberately displays one selected value. Copy stays in Rust and clears the clipboard after the selected 15, 30, or 60 seconds if its contents still match the Latch copy. Clipboard managers may retain a copy despite those controls.

## Locking and the tray

The vault locks after five minutes. Closing the manager locks it and keeps the background app running. The tray provides Open Latch, Lock Vault, and Quit Latch. Quit also stops every command Latch launched. Closing a request popup denies that request.

Locking cannot retract a value already delivered to a process. OS-session locking and suspend integration are not implemented yet.

## Backups

Unlocking requires both your Latch passphrase and device material in the GNOME Keyring. There is no passphrase reset, and losing either one means the vault can't be opened. Once you delete your `.env` files, keep a backup.

**Export.** In the **Backup** tab, enter a backup password twice and choose where to save. The file (`.latchbackup`) holds every project, environment, and secret, encrypted with a key derived from that password (Argon2id, then XChaCha20-Poly1305). Anyone with the file and the password can read every secret. Use a long generated password, and store it somewhere other than the file, such as a password manager. Audit history is not included; each export is recorded in it.

**Restore.** Restore adds a backup's projects to the unlocked vault. On a new machine, create a vault first, then restore into it:

1. In the **Backup** tab, enter the backup password and choose the file.
2. Review the projects it contains, then confirm. Nothing is written until you confirm, and a failed or cancelled restore changes nothing.
3. Open each restored project and choose **Confirm directory…**. Until you do, agent requests never match it, even if a directory exists at the old path.

A restore that would duplicate an existing project's name or directory is refused. Rename or delete the existing project first. Restored records get new identities and are encrypted under this vault's key.
