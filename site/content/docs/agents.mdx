---
title: "Coding agents and the CLI"
---

Agents that support skills can use [the Latch skill](https://github.com/Serendeep/latch/blob/main/integrations/latch/SKILL.md). Other agents can call the CLI directly. Codex, Claude Code, and other tools use the same interface.

## Install the skill

Install Latch for your user account and choose from the compatible agents found on your machine:

```sh
pnpm dlx skills add Serendeep/latch --skill latch --global
```

To install it for Codex and Claude Code without prompts:

```sh
pnpm dlx skills add Serendeep/latch --skill latch \
  --agent codex claude-code --global --yes
```

Start a new agent session after installation. The skill tells the agent when and how to request named secrets; it contains no secret values. Review its [`SKILL.md`](https://github.com/Serendeep/latch/blob/main/integrations/latch/SKILL.md) before installing it.

Register the project directory in the desktop app before requesting access. For a project whose server needs `GITHUB_TOKEN`:

```sh
latch run --project /path/to/project --env development \
  --secret GITHUB_TOKEN --agent codex -- node server.mjs
```

## Approval scope

Repeat `--secret` for each required name. Never pass values as arguments. The popup shows the project, environment, exact command and arguments, the files the command resolves to, requested names, and caller label. Add missing values there, then approve one launch or deny the request.

Latch finds a bare command name such as `npm` using the requesting shell's `PATH`, and follows one `#!` interpreter hop, including the program an `env` line starts. The popup lists each file found and, when it is a link such as a version-manager shim, the file it links to. At launch Latch checks that none of those files changed, then runs the command with that same `PATH`, a small baseline environment, and only the requested secrets. It does not capture the child's input or output. Use `--shell` when intentionally requesting a shell or interpreter; arguments are still passed directly.

The agent label is self-reported audit context, not proof of identity. Requests expire after five minutes. The CLI returns after launch; waiting for completion and cancelling a running job are not implemented.

## When a request fails

If Latch is unavailable, start the desktop application. If the project is unknown, register its directory in the manager. Unlock the vault in the popup when prompted. A denied or expired request needs a new user decision; agents must not retry it automatically. Exit code 12 (`command_not_found`) means the command, its interpreter, or the program `env` starts is not on the requesting `PATH`. No popup is shown and the rejection is recorded in the audit history.
